# Teacher Guide — GitHub Team Launch

## Classroom setup

Use teams of three:

| Role | Required GitHub identity | Main responsibility |
|---|---|---|
| Owner / Maintainer | Repository owner | HTML, review, merge, Pages |
| Collaborator A | Distinct account | CSS |
| Collaborator B | Distinct account | JavaScript |

The Owner should copy the exercise under a **personal GitHub account**, create the new exercise repository as **Public**, and invite the other two students as collaborators. All three students work in the same shared repository; do not use forks.

## Student start flow

```text
Open template
→ Copy Exercise
→ Create public repository
→ wait about 20 seconds
→ open Issues
→ 🚀 GitHub Team Launch Exercise
→ follow the newest unlocked step
```

The workflow posts the next step only after the current evidence passes.

## Teacher grading

Use the `🚀 GitHub Team Launch Exercise` Issue as the source of truth. The exercise finishes at **7/7** and closes automatically.

The only manual spot-check is the public GitHub Project: open the Project URL submitted in Step 1 and confirm that these three Issues are actually present:

- `Build HTML structure`
- `Add page styling`
- `Add JavaScript interaction`

Everything else is checked from GitHub evidence: feature branches, three distinct PR authors, Issue assignments, local-style commits, PR descriptions, file scope, Owner review, a Changes Requested feedback cycle, Owner merges, closed Issues, sync SHA proofs, integrated source, live Pages assets, and three reflections.

## Pilot test

Before using this with a class, run one full pilot with three GitHub accounts. The teacher can be the Owner; two colleagues or students can take CSS and JavaScript. This validates real collaborator permissions and identity-sensitive checks that one account cannot simulate.
