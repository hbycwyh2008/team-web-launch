# GitHub Team Launch

_Learn a real team Git/GitHub workflow by completing an interactive three-person challenge._

## Welcome

This exercise is designed in the style of GitHub Skills: your team performs real work in a copied repository, and GitHub Actions checks your progress and posts the next step automatically.

- **Who is this for:** Students who already know basic repository navigation and are ready to practice collaboration.
- **What you'll learn:** Issues, Projects, local Git, feature branches, commits, pushes, Pull Requests, review, requested changes, merging, syncing `main`, and GitHub Pages.
- **What you'll build:** A small interactive HTML/CSS/JavaScript site published with GitHub Pages.
- **Team size:** 3 — one Owner/Maintainer, one CSS collaborator, and one JavaScript collaborator.
- **How long:** About 45–75 minutes for a first full run.

## How to start this exercise

1. Click **Copy Exercise →** below.
2. Create the new repository as **Public**. Keep the suggested name `team-web-launch`, or use a teacher-approved team name.
3. Wait about 20 seconds, then refresh the new repository.
4. Open **Issues** and find **🚀 GitHub Team Launch Exercise**.
5. Follow only the current step posted in that Issue. The next step appears automatically when the checker validates your work.

[![](https://img.shields.io/badge/Copy%20Exercise-%E2%86%92-1f883d?style=for-the-badge&logo=github&labelColor=197935)](https://github.com/new?template_owner=hbycwyh2008&template_name=github-team-launch-skill&owner=%40me&name=team-web-launch&description=Exercise%3A+GitHub+Team+Launch&visibility=public)

> **Important:** All three students work in the same shared repository. Do not use forks for this challenge, and do not develop directly on `main`.

## What the checker validates

The exercise checks the real GitHub workflow: exact feature Issues, Project evidence, feature branches, three distinct roles, Issue assignments, local-style commits, meaningful commit messages, PR quality, file ownership by role, Owner review, a required **Changes Requested → follow-up commit** cycle, Owner merges, closed Issues, local `main` sync evidence, integrated HTML/CSS/JavaScript, live GitHub Pages assets, and an individual reflection from every team member.

The only teacher spot-check is the Project board itself: confirm that the three feature Issues are actually present in the submitted public Project.
